## Additional stack coverage

Likes/Buzz requests use existing likes/status, likes, likes/respond and MicroBuzz action routes. Social lists include liked/likedYou/matches. Presence and unread update flows use both HTTP and Socket.IO. All receive generic API/request/Mongo timing when executed; this audit does not claim every mutation was performance-tested. Existing chat/payment/migration regression suites cover behavior separately from timing.

The active Posts and Reels gallery feed is **feed/letsbuzz**. Legacy `/api/posts`, `/api/buzz/*` and the separate simple `/api/messages` contract exist but were not substituted for the mobile paths above. Two experiences sharing a route do not imply identical mobile rendering or media costs.

## Existing cache behavior inspected

Shared rbzCache reads memory before AsyncStorage and reports original hit/savedAt values. Custom Discover reads the exact-filter deck then the last deck. LetsBuzz persists up to 80 feed entries. Thread cache retains its existing room/message behavior. Inbox TTL is 5 minutes and its separate presence TTL is 2 minutes; Social Stats count/list TTLs are 2 minutes. These are configuration values, not measured read latencies. Existing stale rendering, prefetching, focus refresh and background refresh behavior was preserved.

Instrumentation identifies cache reads and cached/fresh state commits on these paths. A cache hit does not prove pixels appeared before a response, and no device-derived cache hit-rate is available. Direct storage outside these readers may appear only in broader startup timings.
