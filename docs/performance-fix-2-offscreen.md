## Lifecycle choices that preserve behavior

The native root pager in `app/(tabs)/(root)/_layout.tsx` deliberately uses `lazy: false` so neighboring screens appear during swipes. Hidden routes such as MicroBuzz also remain mounted after visiting them. Those mounting choices explain why unmount-only cleanup was insufficient. Both navigation layouts and the Let'sBuzz Posts/Reels/fullscreen routing remain unchanged. There is no screen freezing, tab unmounting, cache deletion, or navigation redesign.

`useScreenActivity` combines route focus with `AppState === "active"`. Its direct getters let async work check current focus/app state before React finishes the corresponding transition. Each AppState subscription is removed on unmount. `useRetainedState` retains necessary async/realtime results and composes functional updates while hidden, then flushes them on reactivation. The producers of recurring work are independently stopped; retaining state is not a substitute for stopping timers, scans, animations, or players.

MicroBuzz needs a distinction between an invisible radar and an intentionally live user. Read-only inspection of the local backend found a five-minute session freshness window in `server/services/microbuzzSessionService.js` and a five-minute selfie TTL in `server/routes/microbuzz.js`. Stopping all live presence work on a tab switch would silently expire the user's session/selfie. Therefore:

- Visible + live: the existing 2-second radar cadence remains, with presence refreshed when due at the existing 5-second threshold.
- Other screen + app foreground + live: only a 5-second presence cadence remains, including the existing early selfie refresh when needed. No radar read or hidden visual commit.
- App inactive/background: periodic scheduling stops. Live intent/selfie/state remain; foreground resumes work and refreshes expired presence/selfie through the existing endpoints. The existing server expiry still applies during a long absence.
- Explicit Stop still clears the queue/nearby state and uses the existing deactivation endpoint. No automatic deactivation was added on tab changes.

Shared sockets are never disconnected by these screens. Incoming queue order/deduplication, matches, comment/gift events, profile cache/session writes, manual refresh, and explicit save/upload actions remain. Finite action completions and toast expiry can finish; their retained state does not repaint a hidden screen. Focus/app-state transitions and changes from shared parents/providers can still cause legitimate renders. This fix does not claim that every offscreen React commit throughout the app disappears.

Reel playback resumes from the last native status report (500 ms cadence); the native player must prepare again after being unloaded. Feed/list scroll state stays mounted. The fullscreen wrapper uses the same Reel component and receives the same lifecycle behavior. Switching Posts/Reels/fullscreen retains its existing mount behavior.

The root tab bar also owns unread-related work and a badge pulse. That ownership was inspected but left for the explicitly deferred unread/Chat work. Other screens' polling and the later media/profile cleanup were not refactored. Existing one-time child cache reads and user-initiated feature work remain.
